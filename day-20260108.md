## WORK

### Business Context

When materials are picked from inventory for a work order (WO) in Scale WMS, OIC must receive that pick confirmation and forward it to monocles-app. This moves inventory to Work In Progress (WIP) and keeps systems aligned.

### The Flow

1. Scale WMS picks materials → sends pick confirmation payload

2. OIC receives the payload (your integration)

3. OIC forwards it to monocles-app (pass-through)

## Key Technical Details for Implementation

### 1. When Messages Arrive

- Real-time (triggered by pick confirmations)

- Up to 2000 records per message

- Multiple files per work order (e.g., frames, lenses)

### 2. Payload Filtering Criteria

Filter for:

- OrderType = 'Work Order' (ignore Transfer/Sales orders)

- Valid work orders only (exclude cancelled/closed)

- Organizations: LSLO, LLAS

### 3. Expected Payload Structure (from WMS)

The incoming payload from Scale WMS should include:

|Field|Description|Notes|
|---|---|---|
|OrderType|Must be 'Work Order'|Filter criteria|
|ERP_ORDER|Work Order Number|Required|
|Item|UPC code|Need to map to Oracle item number|
|Warehouse|Organization code|Maps to OrganizationCode|
|PickFromSubinventory|Subinventory code|Maps to SubinventoryCode|
|Picked|Transaction date/time|Format: 2025-11-21 08:51:57.035751|
|PickedQuantity|Quantity picked|Maps to TransactionQuantity|
|SerialNumber|Serial number(s)|Optional (only for serialized items)|

### 4. For Your Pass-Through Implementation

Since you're only forwarding to monocles-app:

Integration Type: REST API Trigger → REST API Invoke

Flow:

  1. OIC receives REST payload from Scale WMS

  2. Validate/filter: OrderType = 'Work Order'

  3. Forward payload to monocles-app (as-is or with minimal transformation)

  4. Return response to Scale WMS

Key considerations:

- Preserve the original payload structure for monocles-app

- Validate the required fields are present

- Handle errors and return appropriate responses

- Ensure proper authentication/authorization for both systems

### 5. Important Business Rules to Note

- Serial numbers: only required for serialized items; may be missing for non-serialized items

- Partial picks: allowed (controlled by Oracle tolerances)

- Date format: WMS sends with microseconds; trim if needed: 2025-11-21 08:51:57.035751 → 2025-11-21 08:51:57

### 6. Error Handling Requirements

The document specifies these error scenarios (relevant even for pass-through):

- Credentials expired/locked

- Missing required data

- Work order validation failures

- Data transformation errors

Implement error logging/notifications per your organization's framework (JIRA tickets on failure).

## Implementation Steps (Suggested)

1. Create REST trigger adapter: receive POST from Scale WMS

2. Add validation: check OrderType = 'Work Order' and required fields

3. Create REST invoke adapter: forward to monocles-app endpoint

4. Implement error handling: capture failures, log, notify

5. Map responses: return appropriate HTTP status codes to Scale WMS
