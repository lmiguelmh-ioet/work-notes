## Introduction

**EasyPost** is a shipping API platform that simplifies carrier integration by providing a unified interface to track shipments across multiple carriers. Within Helios, EasyPost trackers are created when a shipment label is generated, enabling real-time visibility into package location and delivery status.

### Key Capabilities

- **Multi-Carrier Support**: Works with USPS, UPS, FedEx, DHL, and many other carriers
    
- **Real-Time Tracking**: Provides webhook notifications when tracking status changes
    
- **Automatic Carrier Detection**: Can determine the carrier from a tracking number if not specified
    

## Tracker Creation

### Overview

#### What is a Tracker?

A tracker in EasyPost is an object that monitors a package's status and location as it moves through a carrier's shipping network. Once created, EasyPost polls the carrier for updates and provides webhook notifications when tracking information changes.

#### Why Create Trackers?

Trackers enable:

- Real-time shipment status monitoring
    
- Automated carrier event processing
    
- Customer delivery notifications
    
- Exception handling for delivery issues
    
- Visibility into the shipment lifecycle
    

### High-Level Flow

`shipment_label_created signal ↓ create_tracker_for_shipment() ↓ [Check: Unsupported Carrier?] → Yes → Log & Exit ↓ No [Get Carrier External Name for EasyPost] ↓ [Feature Flag: create_easypost_tracker_in_bg_task?] → Yes → Add to Background Task Queue ↓ No [Feature Flag: create_easypost_tracker_in_sqs_queue?] → Yes → Publish to SQS FIFO Queue ↓ No ↓ [Feature Flag: direct_easypost_tracker_creation?] → Yes → Synchronous Creation ↓ ↓ get_or_create_tracker_for_shipment() ↓ ↓ ↓ [Feature Flag: skip_easypost_tracker_existence_check?] ← - - - - - - - -┘ ↓ No get_tracker_by_tracking_code() (3-month lookback) ↓ [Tracker Exists?] → Yes → Log "easypost_tracker_already_exists" → Process Existing Events ↓ No create_tracker(carrier, tracking_code) ↓ [API Error 422?] → Yes → Retry create_tracker(tracking_code) without carrier ↓ No [Success] → Process Events from Tracker`

#### Step 1: Shipment Label Creation

When a shipment label is created in Helios, a signal `shipment_label_created` is emitted.

**Source**: `wp/signals.py` (signal definition)

#### Step 2: Signal Handler Invocation

The signal handler `create_tracker_for_shipment_callback()` is triggered.

**Code Location**: `wp/cases/carrier_events/tracker.py:152-163`

#### Step 3: Carrier Validation

Before creating a tracker, the system validates carrier support.

**Unsupported Carriers**:

`UNSUPPORTED_CARRIER_SCAC_LIST = ["LDLB"]`

**Validation Logic**:

- Checks the carrier SCAC code against the unsupported list
    
- Logs the event if the carrier is unsupported
    
- Skips tracker creation for unsupported carriers
    

**Code Location**: `wp/cases/carrier_events/tracker.py:213-223`

#### Step 4: Carrier External Name Resolution

The system maps internal carrier IDs to EasyPost carrier names.

**Database Table**: `logistics.external_carrier_names`

**Sources**:

- `wp/cases/carrier_events/tracker.py:224-229`
    
- `wp/constants.py:630-634`
    

#### Step 5: Feature Flag-Based Routing

Three feature flags control the tracker creation method:

- Background Task (Async)
    
- SQS Queue (Delayed Async)
    
- Direct Creation (Default)
    

#### Step 6: Tracker Existence Check (Optional)

If the feature flag: `skip_easypost_tracker_existence_check` is enabled, it skips checking if a tracker already exists for the tracking code to reduce API calls, but may create duplicate trackers because EasyPost trackers are NOT idempotent across different API keys.

#### Step 7: API Call to EasyPost

- **Production Environment**: Makes an HTTP POST request to `https://api.easypost.com/v2/trackers`
    
- **Non-Production Environment**: Returns a mocked tracker response
    

**Source**: `wp/logistics/easypost/tracker.py:33-76`

#### Step 8: Error Handling

- HTTP 422 (Unprocessable Entity): Retry without the carrier parameter
    
- Other errors: Propagate exception
    

**Source**: `wp/logistics/easypost/tracker.py:86-102`

#### Step 9: Process Existing Events

- Process any existing tracking events associated with the new tracker
    
- Links tracker to the shipment in the Helios database
    

**Source**: `wp/cases/carrier_events/tracker.py:104-109`

### API Endpoints

#### Authentication Method

EasyPost uses HTTP Basic Authentication with the API key as the username and an empty password.

`from requests.auth import HTTPBasicAuth auth = HTTPBasicAuth(username=api_key, password="")`

#### Create Tracker Endpoint

**Endpoint**: `POST /v2/trackers`

**Base URL**: `https://api.easypost.com/v2`

**Authentication**: HTTP Basic Auth (API Key as username, empty password)

**Request Body**:

`{ "tracker": { "tracking_code": "string", "carrier": "string (optional)" } }`

**Response** (Success - 201 Created):

`{ "id": "trk_...", "object": "Tracker", "mode": "production", "tracking_code": "string", "status": "string", "status_detail": "string", "created_at": "2026-05-05T00:00:00Z", "updated_at": "2026-05-05T00:00:00Z", "signed_by": "string", "weight": null, "est_delivery_date": "2026-05-05T00:00:00Z", "shipment_id": "shp_...", "carrier": "USPS", "tracking_details": [], "carrier_detail": {}, "public_url": "https://track.easypost.com/...", "fees": [], "finalized": true, "is_return": false }`

**Source**: `wp/logistics/easypost/tracker.py:58-66`

#### Get Tracker by ID Endpoint

**Endpoint**: `GET /v2/trackers/{tracker_id}`

**Parameters**:

- `tracker_id` (path, required): 36-character tracker identifier
    

**Response** (Success - 200 OK): Same structure as Create Tracker response

**Response** (Not Found - 404): Returns `None` in application logic

**Source**: `wp/logistics/easypost/tracker.py:79-102`

#### List Trackers by Tracking Code Endpoint

**Endpoint**: `GET /v2/trackers`

**Query Parameters**:

- `tracking_codes[]`: Array of tracking codes to search
    
- `start_datetime`: ISO 8601 datetime (e.g., `2026-02-05T00:00:00.000000Z`)
    
- `end_datetime`: ISO 8601 datetime
    

**Use Case**: Retrieve existing trackers by tracking number within a date range

**Note**: Due to tracking code reuse by some carriers, this endpoint returns trackers from the last 3 months (configurable via `num_months` parameter)

**Source**: `wp/logistics/easypost/tracker.py:105-143`
