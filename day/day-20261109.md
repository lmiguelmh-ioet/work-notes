## Insights/Ideas
- 09:14 — The IDCS login page's external-IdP button can sit below the fold; a "no Okta button" report does not mean the IdP policy is missing. Ask the user to scroll before changing config.
- 09:46 — A credential printed through the agent Shell lands in a persistent terminal log, not only on the user's screen. Signature: any `--show-token`-style demo output. Treat demo prints as transcript-persistent; the token TTL is the only mitigation.
- 09:46 — A one-shot loopback OAuth listener can be consumed by any shaped stray request (`GET /oauth/callback?error=x`) during the browser window. It costs the run, not the token. Tolerate-and-continue beats fail-fast for listener robustness.
- 11:05 — Cursor-sandboxed shells export proxy vars (`HTTP(S)_PROXY=127.0.0.1:55253`); httpx honors them and the sandbox proxy 403s arbitrary POSTs. Signature: `httpx.ProxyError: 403 Forbidden` right after a successful browser callback. Fix: rerun the command with full permissions (direct network).
- 11:05 — IDCS error verbosity is per-endpoint: introspect names the unauthorized client verbatim, but token/revoke return an undifferentiated HTTP 400. A missing inbound trust is invisible from outside; validating it needs the admin side or an Oracle SR.
- 11:36 — AI web-search summaries confabulate OCI console paths. The fake "Identity propagation trusts" console menu traced to an AI summary whose own sources lacked it. Verify click-paths against primary Oracle docs. Signature: plausible console labels with no documented anchor.
- 11:36 — An Okta custom authorization server's access-token `sub` defaults to the user login (email form), not the opaque `00u…` ID. The `00u…` shape is the org-AS and ID-token default. Okta's example payload shows the org-AS shape and misleads.
- 13:06 — The modern OCI console renders Allowed operations per app type. A public Mobile app shows only "On behalf of" and cannot be introspect-enabled from the console. Expect this before asking IAM to enable introspection on a public client.
