## Insights/Ideas
- 09:40 — Capturing tokens from a browser SSO without automation detection: skip Playwright/CDP entirely. Launch plain Chrome with `--log-net-log=<file> --net-log-capture-mode=Everything`, log in by hand, then extract by decoding the log's `"bytes"` blobs. Bodies are chunk-split — correlate blobs by the request's source id; a single-blob grep for `SAMLResponse` misses them.
- 09:40 — IDCS token endpoint error codes are non-diagnostic: the same 400 `invalid_request` covers an unknown grant name, an untrusted assertion, and a missing scope. Never read grant enablement from the error code; use the discovery document plus differential probes.
- 09:40 — IDCS "Trusted" client type means the client signs its OWN user assertions. For third-party-IdP assertions (Okta-signed), the documented shape is a Confidential app plus the existing SAML IdP registration — asking for a "trusted client" in a registration request misroutes it.
- 10:00 — Direct third-party IdP access tokens never authenticate to Fusion REST (field-proven 401): Oracle validates issuer/audience against its own IDCS registrations, and Okta cannot set `iss` to anything but its own AS URL. The sanctioned bridge is the 3-legged auth-code flow through the existing SSO federation — the console session carries through `/oauth2/v1/authorize`.
- 10:25 — Old vendor articles mislead by omission: Oracle's 2026 user-context delta landed in the identity layer's release notes (OCI IAM JWT token exchange Jul 2025, ID-JAG redemption Oct 2026), not in the Fusion OAuth docs, which through 26D still teach the 2021 jwt-assertion pattern. When a vendor doc looks stale, check the adjacent platform's release notes before concluding nothing changed.
- 11:14 — Before designing an Oracle client flow, check github.com/oracle for a reference implementation. The FSCR repo (Oct 2026) ships the exact auth-code + PKCE client shape plus the 26D admin click-path, which turns a registration request into "mirror Oracle's own setup" instead of arguing from community blogs.
- 11:58 — Posting a PR review from the agent's last-written YAML instead of re-reading the file posts comments the user deleted mid-review. Signature: the user edits the draft between the rewrite and "post it". Always re-read the draft in the same turn as the post call.
- 13:25 — An approval-card skip is a stop signal for the whole batch, not a skip-one-continue vote. Signature: the user dismisses one item mid-batch. Stop and re-confirm the rest; nine PR thread replies on #1188 posted after that signal.
- 13:25 — "Close this" is not post confirmation. Posting to GitHub needs an unambiguous "post it" after the draft review; ambiguous wrap-up phrasing means wrap up only. When in doubt, ask which.
- 13:36 — Discover any Oracle pod's identity domain without admin access: GET the pod's `/fscmUI/adfAuthentication` unauthenticated and read the `location` header — it 302s to the stripe's `/oauth2/v1/authorize`, and `idcs_app_name` reveals the patch level (`FAAppResource_11-13-26-07` = 26C).
- 13:36 — An environment upgraded to OCI IAM identity domains keeps its legacy `idcs-<hash>` stripe URL and discovery document (dev1, verified 2026-11-06). After any identity upgrade, re-probe `.well-known/openid-configuration` before touching client config.
- 14:24 — OIC schedule parameters are empty on scheduled runs; only ad-hoc submissions fill them. A mapper that concatenates a suffix onto an empty param fabricates a payload (`"T00:00:00"`) instead of omitting the element. Signature: the integration works when tested ad hoc but every scheduled run faults on the downstream call.
