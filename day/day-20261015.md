## Insights/Ideas
- 09:42 — monocle's API suite flakes under plain `pytest -n`: failures wander across unrelated suites and pass standalone. `make test-api` adds `--dist loadgroup`, which keeps resource-sharing test groups on one worker. Always use the make target.
- 11:34 — Bare `poetry run mypy` in monocle exits 0 but checks nothing ("Missing target module, package, files, or command"). The Makefile passes explicit targets: `mypy monocle_integrations "test" infrastructure/local_env`. A green no-op is worse than a failure.
- 11:44 — Stack pushes that skip mypy locally let contract breaks reach CI. Signature: a mypy `list-item` error in a file with zero branch diff — the contract changed in a sibling commit. Run `make check-format-parallel` before every stack push.
- 09:42 — A backgrounded shell task keeps running against the stack. Two concurrent pytest suites on one LocalStack contend and flake. Check `docker top <container>` before launching a suite.
- 12:33 — Full `make test-api` runs 5+ minutes against 47 seconds for the full coverage gate. Piping its output through `tail` hides all progress, so a healthy run looks frozen.
- 12:34 — `contract-tests` failing with `No records in Oracle` (pick-slip/put-away fixtures) is environmental: the live pod lost the fixture rows. Main's pipeline failed the same three tests 10 minutes before the PR run. Compare with main before suspecting the diff.
