 ```
 1. Console “Test” vs Function URL
In the Lambda console, Test runs an invoke on the function (direct Lambda API), not necessarily the same path as hitting the Function URL over HTTPS. For “does the URL work with IAM?”, you need a signed HTTP request to that URL.

2. curl with SigV4 (built in on recent curl)
Your URL is in us-east-1. Signing uses service lambda.

Long-term IAM user (access key + secret):

export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
export AWS_REGION=us-east-1
export FURL='https://sjlqdgbb5mesmduz4pw5oj6fsa0ykkxk.lambda-url.us-east-1.on.aws/'
curl -v "$FURL" \
  --aws-sigv4 "aws:amz:${AWS_REGION}:lambda" \
  --user "${AWS_ACCESS_KEY_ID}:${AWS_SECRET_ACCESS_KEY}"
Temporary credentials (STS / SSO / assumed role), add the session token:

curl -v "$FURL" \
  -H "x-amz-security-token: ${AWS_SESSION_TOKEN}" \
  --aws-sigv4 "aws:amz:${AWS_REGION}:lambda" \
  --user "${AWS_ACCESS_KEY_ID}:${AWS_SECRET_ACCESS_KEY}"
You need curl 7.75+ with AWS SigV4 support (curl --version and look for features mentioning AWS).

3. Credentials from the AWS CLI profile
If you already use aws configure or SSO:

export AWS_REGION=us-east-1
export FURL='https://sjlqdgbb5mesmduz4pw5oj6fsa0ykkxk.lambda-url.us-east-1.on.aws/'
# Example: force a profile
export AWS_PROFILE=your-profile
CREDS=$(aws sts get-caller-identity 2>/dev/null)  # optional sanity check
# For SSO / assumed role, use aws configure export-credentials (CLI v2) or parse env from `aws sso login` session
For static keys in a profile, you can pull them (less ideal than env from SSO):

curl -v "$FURL" \
  --aws-sigv4 "aws:amz:$(aws configure get region):lambda" \
  --user "$(aws configure get aws_access_key_id):$(aws configure get aws_secret_access_key)"
With SSO, prefer exporting credentials via aws configure export-credentials --format env (CLI v2) and then use the curl + x-amz-security-token form above.

4. awscurl (alternative)
pip install awscurl
awscurl --region us-east-1 --service lambda 'https://sjlqdgbb5mesmduz4pw5oj6fsa0ykkxk.lambda-url.us-east-1.on.aws/'
It uses your default AWS credential chain (profile, env, SSO after login, etc.).

5. IAM
The caller needs permission to use the function URL, e.g. lambda:InvokeFunctionUrl (and often lambda:InvokeFunction) on that function. Without it you’ll get 403 Forbidden even with a valid signature.

Summary: There is no separate “invoke this URL” subcommand required: treat it as HTTPS + SigV4 with service lambda and region us-east-1. The easiest paths are curl --aws-sigv4 with explicit keys + session token when needed, or awscurl on top of your normal AWS profile/SSO.
 ```
