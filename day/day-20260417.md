## Prompt architectures:
- Single orchestrator with skill registry (router + executor).
	- One agent reads the issue, picks a skill (JIRA / AWS / OIC / ERP / KB), calls the right MCP or API wrapper, aggregates results, and closes the loop. Simplest operationally; risk of prompt bloat unless skills are modular (separate files / short descriptions only in the main prompt).
- Planner → worker(s) (two-stage)  
	- Orchestrator only decomposes the issue into steps, dependencies, and acceptance checks; a worker prompt (or the same model in a second call) executes each step with a narrower context. Good for long tickets and auditability; needs clear handoff format (JSON plan, step status).
- Hub-and-spoke “specialist” sub-agents
	- Orchestrator is thin: classify intent, delegate to specialist prompts (JIRA specialist, AWS specialist, …), merge outputs. Fits many tools and keeps each specialist prompt small; needs strict contracts (input/output schema) and deduplication of work.
- Hierarchical supervisor (tree)  
	- A top supervisor handles prioritization and escalation; mid-level agents own domains (e.g. “integrations platform”); leaf agents run concrete tools. Useful if you have SLAs, security boundaries, or human-in-the-loop gates; heavier to run.
- Event-driven / ticket state machine
	- Not only LLM prompts: orchestration is a workflow (e.g. “triage → reproduce → fix → verify → update JIRA”). The LLM fills transitions; code enforces allowed transitions and stores state. Best for repeatable issue types and compliance.
- RAG-first triage
	- Orchestrator always queries the knowledge base first, then decides whether the issue needs live tools. Reduces mistaken AWS/OIC actions; tune when KB is allowed to block tool use vs. only inform.
- ReAct / tool-loop with guardrails  
	- One prompt that explicitly loops: think → pick tool → observe → repeat until done, with hard limits (max steps, allowlist of tools, confirmation for destructive ops). Easiest to prototype; needs strong tool descriptions and logging.

## Ticket state machine
- Prompt-only phases (soft state machine)
	- You put rules like: `PHASE: TRIAGE → INVESTIGATE → MITIGATE → VERIFY → REPORT`, and ask the model to announce the phase. Pros: zero infra. Cons: unreliable under pressure/long tasks; hard to test.
- Hybrid (recommended for local MVP)	
	- Prompt defines what each phase _means_ and what evidence to collect.
	- Thin local runner (10–50 lines, or LangGraph) enforces: allowed `phase` values, order, and “cannot call destructive tools unless phase = MITIGATE and flag approved.”
	- The model outputs something structured, e.g. JSON: `{ "phase": "INVESTIGATE", "next_actions": ["kb_search", "read_cloudwatch"], "done_criteria": ["..."], "blockers": [] }`
	- Your runner checks `phase` is legal from current state, executes tools outside the model if you want strict safety, then feeds results back. That is a real state machine with LLM-filled slots.
- Code-defined graph (hardest guarantees, still local)
	- LangGraph (or hand-rolled while + dict) defines nodes and edges explicitly: triage_node → retrieve_kb → jira_read → .... The LLM is called inside nodes with narrow prompts. Pros: testable, auditable, least ambiguity. Cons: more upfront coding than “one big prompt.”

- In each SKILL define risk levels: write, destructive

class FileReaderToFileStorageBridgeError(Exception):  
    pass


class FileReaderToFileStorageBridge:
    """
    Convenience facade: ``RecentDayPrefixDiscovery`` + ``FileReaderToStorageCopier``
    + ``RemoteDiscoveryToStorageSync`` with a single constructor matching the
    previous monolithic bridge.
    """

    def __init__(
        self,
        *,
        file_reader: ContextFileReader,
        file_storage_action: FileStorageAction,
        dest_directory: str,
        prefix: str,
        max_recent_days_to_try: int = 2,
        file_name_prefix_strategy: Optional[Callable[[date], str]] = None,
        reference_date: Optional[date] = None,
    ) -> None:
        self._copier = FileReaderToStorageCopier(
            file_reader=file_reader,
            file_storage_action=file_storage_action,
        )
        self._sync = RemoteDiscoveryToStorageSync(
            discovery=RecentDayPrefixDiscovery(
                file_reader,
                prefix,
                max_recent_days_to_try=max_recent_days_to_try,
                file_name_prefix_strategy=file_name_prefix_strategy,
                reference_date=reference_date,
            ),
            copier=self._copier,
            default_dest_directory=dest_directory,
        )

    async def copy_files(self, *, dest_dir: str | None = None) -> list[str]:
        return await self._sync.sync(dest_dir=dest_dir)

    async def _copy_file(
        self,
        *,
        source_dir: str,
        dest_dir: str,
        source_file_name: str,
        dest_file_name: str,
    ) -> str:
        return await self._copier.copy_one(
            source_dir=source_dir,
            dest_dir=dest_dir,
            source_file_name=source_file_name,
            dest_file_name=dest_file_name,
        )
