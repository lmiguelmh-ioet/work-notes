## WMS-I-1021 Scale to Oracle / SF Pack Confirm

- Entry: `POST /wms/pack-confirmation`. 
- Sales Orders and Transfer Orders in the same payload run concurrently.
- Returns 201 when everything succeeds. Any failure, 500.

### Sales Orders

- One FIFO message per shipment (SNS `labs-fulfill-events-*.fifo`, or Helios FIFO SQS).
- Deduplication ID = `SHA256(warehouse + ship_set + FR ids + CreatedTimestamp from header)`

#### On retry
- We always resend every SO:
	- Same CreatedTimestamp, within ~5 min -> FIFO drops it.
	- After ~5 min, or if new `CreatedTimestamp` -> duplicate pack event sent through SNS/SQS.

#### Fix
- Persist published `transaction_id`s and skip them on retry.
- Return partial results.

### Transfer Orders
- Per shipment: read Oracle lines, filter, map WMS containers to lines, split per LPN, create packing units, pack.
	- filter keeps only `Staged` lines with no packing unit. Already packed/not staged are skipped. If nothing is left, error (a successful TO fails on retry).

#### On retry
- Map: walks the full WMS container list, filter only drops Oracle lines, not LPNs; so if LPN-A is already packed and LPN-B is not, A is skipped as a line but still mapped first onto the leftover unpacked line (what was supposed to be for LPN-B), so that line can be packed into A again. B is left unmatched.
- Split: might create extra Oracle line if one unpacked line is given two or more LPNs. (line qty 10, WMS A=4 and B=4, remainder=2). Retry uses A/B onto remainder + split lines -> extra split. If A=5, B=5 (no remainder), retry does not split again.

#### Fix
- Map: After pack succeeds persist `order_number` + `lpn`, `status=PACKED`, and `new_line`, `qty`. On retry: if the WMS `LicensePlate` is `PACKED`, do not map it.
- Split: same row (`order_number` + `lpn`). After split: `from_line`, `new_line`, `qty`, `status=SPLIT`. On retry, pack `new_line` for that LPN; do not remap/re-split. Fallback use an heuristic: match unpacked lines by item + qty, remainder last.
- Return partial results.
