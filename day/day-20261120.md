## Insights/Ideas
- 09:20 — BIP window-arm design: a re-selection fold keyed only on `GREATEST(business_date, creation_date)` silently drops rows whose values are stamped late with old dates (carrier feeds post days later). Every arm needs the write-date backfill catch (`pod_last_update`-style GREATEST of last-update dates) plus an order-numbers recovery mode. Signature: rows exist with the right business date but never emit.
- 10:02 — `git apply` of a `git diff --no-index` patch fails with `No such file or directory` even when the target exists: the headers carry absolute paths at mixed depths, so the strip level resolves differently per side. Fix: sed the `a/`/`b/` prefixes to repo-relative paths before applying.
- 10:12 — A squash merge upstream can absorb a stacked branch's own edits. The stacked PR's draft description then claims behavior already on main. Signature: `git diff <merge-base>..HEAD` shows no change in a file the description names. Verify each bullet against the merge-base diff before posting.
- 10:26 — A defensive control that guards infrastructure that does not exist yet is scope, not security — worse when it forces a runtime dependency. Signature: the dependency sits in runtime deps only for the guard, and the guarded pipeline ships in a later ticket. Cut the guard; let the later ticket bring it.
- 11:05 — Verify provenance before cutting a "new" dependency: `git log -S '<name>' -- pyproject.toml` finds the introducing commit. The `7cfc8de` descope assumed `opentelemetry-sdk` arrived with PR 3; it actually landed in #7, voiding the rationale and forcing a same-day revert.
- 10:35 — "Recoverable via P_ORDER_NUMBERS" over-promises when the hold is a NULL business date, not a window miss: order-numbers mode skips window checks but not top-level conjuncts like `first_delivery IS NOT NULL`. Signature: a re-run by order number emits nothing for a row that looks selected. Phrase recovery notes by which conjunct the mode actually bypasses.
- 14:35 — A Lambda cold start can log `INIT_REPORT ... Status: timeout` at the 10-second init limit and still serve the request normally. Signature: `Status: timeout` at ~9,999 ms followed by a normal START→END→REPORT in the same stream. It is not a failed invocation.
- 14:35 — The arbiter report trims SQL to fit its bind limit, so the generated wrapper file is not what executes. The log's own `<P_SQL>` payload is the exact executed text. Pull evidence SQL from the log, not the generator output.
