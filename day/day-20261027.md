## Insights/Ideas
- 07:01 — OEH tickets from S3-event failures are named `s3_event_handler`, not the RICE id. RICE-id searches miss them. 10-26 example: OEH-88909 to OEH-88914 were invisible as IN-I-2019. Search by request id or by the generic function name.
- 09:39 — Direct Fusion SOAP repros with curl: send `Content-Type: text/xml` for the SOAP 1.1 templates (`application/soap+xml` gets an `env:VersionMismatch` fault before business logic runs) and pass `--compressed` (fa pods gzip fault bodies; a saved response reads as binary).
- 09:39 — AR-856537 / AR_REF_USR_LMT_NOT_SET ("You don't have approval limits set up for refunds") is a per-user AR setup error, not a payload problem. When refunds that worked last week fail with it on a shared pod, suspect a weekend setup wipe; a raw curl with the same envelope proves it in minutes.
- 12:19 — Jira evidence comments cannot reference local files. A ticket reader sees no working tree. Attach only what re-pulling cannot cover (short-retention logs, curl traces). Everything else gets a re-pull pointer (request id, S3 key, query). Rule lives in the jira-qa-evidence skill.
- 11:39 — jq `.body..` is invalid syntax; the pipe form is `.body | ..`. The bad form aborted the resolve-comment execute path under `set -e`, after the assign and transition writes had already landed. Dry runs never exercised that path. Lesson: test the write path of a script, not only the dry run.
- 11:39 — CloudWatch Insights queries on global patterns (`/Processed/ and /success/`) saturate in busy prod log groups: 50 rows inside 8 minutes of a 60-minute window, so the one winner row never appears. Scope by the sibling request ids parsed from the ticket TO's own routing lines instead.
