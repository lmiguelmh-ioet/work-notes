## Insights/Ideas
- boto3 DynamoDB condition objects (`Key`/`Attr`) implement value equality. Unit tests can assert query conditions directly instead of rendered expression strings or attribute-value maps. Trigger: mocking `table.query` and asserting on `KeyConditionExpression`.
- `_domain/_use_cases/` in monocle_integrations is a legacy package down to `health_check` after steady removals. New facade read operations should be direct reader attributes wired in the activation PR. Bonus: identity assertions (`is`) in the facade test then catch swapped same-typed kwargs. Trigger: a plan mirrors `health_check` or adds a pass-through use case under `_use_cases`.
- Pytest-xdist per-worker scoping isolates only within one pytest run. Two concurrent suites against one LocalStack contend and flake (today: 8-12 shifting failures in S3-dependent API tests). Give each run its own stack. Trigger: parallel agents both running `make test-api` style suites.
- Poetry's "The virtual environment ... seems to be broken. Recreating virtualenv" means the repo `.venv` (shared through the docker mount) mismatches the container image's pyenv Python. The recreate wipes the installed deps for every container that shares the mount. Replica containers must reuse the main stack's images (retag), never rebuild. Trigger: that log line, then "Command not found: pytest".
- Docker Compose `container_name` is also a network DNS record. Dropping it for project-scoped names breaks config that references the old hostname. Keep the old names as network aliases. Both spellings circulate in repo config and tests: `mock-manhattan-scale` (service) and `mock_manhattan_scale` (container_name). Trigger: "Name or service not known" for a mock host after a compose rework.
- Buildkit "error reading from server: EOF" mid-build means the Docker Desktop daemon restarted, for example to apply a memory change. It is not a Dockerfile problem. Retry after the daemon settles.
