## Structure

- One test class per SUT when it helps grouping; name tests `test__<behavior>__<condition>` (double underscore segments).
- Prefer **`@pytest.fixture` factories** named `test_data_factory` and/or `dependencies_factory` that return `Callable[..., ...]` and build **requests, domain objects, and mocks** in one place. Override behavior via `**kwargs` / `side_effect`, not copy-paste setups.
- Use **`faker`** for identifiers and text; use **`pytest_mock.MockerFixture`** / `mocker` for async and sync mocks.
- **Async SUT:** `@pytest.mark.asyncio` on the test; use `AsyncMock` and `assert_awaited_once_with` / `assert_not_awaited` as appropriate.

## Assertions

- Assert **outputs** and **collaboration** (who was called, with what). For exceptions, use `pytest.raises` and check message, `__cause__`, or attachments when that is the contract.
- Use **`@pytest.mark.parametrize`** for equivalent cases (valid/invalid branches, multiple inputs).

## Do not

- Do not test private methods; test behavior through public API.
- Do not add comments unless necessary for non-obvious flow (project convention).
