# OTCM-139192 — Expose transaction_failures read API on the custom-auth Lambda

## Context

[OTCM-139192](https://warbyparker.atlassian.net/browse/OTCM-139192) (Story, assignee Luis, reporter Gabriel Viera): add read APIs on monocle-app for the DynamoDB `transaction_failures` table so OMG-UI can render an ops queue of failed integration transactions. Query **only** through existing keys/GSIs — never `Scan`.

- Table + GSIs exist ([OTCM-138120](https://warbyparker.atlassian.net/browse/OTCM-138120), Done): PK `failure_id`; GSIs `status-lastFailedAt`, `riceId-lastFailedAt`, `orderId-lastFailedAt` (all SK `last_failed_at`, ISO-8601 string). Statuses: `FAILED` / `RETRYING` / `RESOLVED` / `IGNORED` / `DEAD`.
- Blocked by [OTCM-139191](https://warbyparker.atlassian.net/browse/OTCM-139191) (AVP middleware + `/v1/me/permissions`; To Do) — API logic may start earlier in shadow mode. Auth target: CF JWT + AVP (`WP::Action::"viewTransactionFailures"` on `WP::Service::"monocle-integrations"`); HMAC off on these paths. Reference: [AVP Middleware/SDK spec](https://warbyparker.atlassian.net/wiki/spaces/SRE/pages/9900687399/Technical+Specification+AVP+Middleware+SDK).
- Consumer: [OTCM-139193](https://warbyparker.atlassian.net/browse/OTCM-139193) (OMG-UI table) — browser → `omg.{env}.warby.io/monocle-api/*` → Cloudflare Worker → custom-auth Function URL, forwarding `CF-Authorization` / `cf-access-jwt-assertion`.
- No RICE folder/FSD exists for this work (cross-cutting error-handling infra, epic [OTCM-106900](https://warbyparker.atlassian.net/browse/OTCM-106900)); the ticket description is the spec (confirmed 2026-10-02, Q7).

### Repo facts verified (2026-10-02)

- Write side exists: `_domain/_ports/_transaction_failure/` (`TransactionFailure` + `TransactionFailureRecordAction`), `_adapters/_transaction_failure_actions/DynamoTransactionFailureRecordAction`, exception module `_domain/_exceptions/_transaction_failure_exceptions.py`.
- `Settings.aws_dynamodb_transaction_failures_table_name` already populated in every `_config/*.yml` (incl. ott); `Adapters.__init__` already builds a Dynamo client for the table. No new settings needed for the reader.
- Two Lambdas share the zip: IAM (`CUSTOM_AUTH=false` → `*.yml` → `enable_authentication: false` → **no auth middleware runs**) and custom-auth (`CUSTOM_AUTH=true` → `*_auth.yml` → `enable_authentication: true`, Function URL `NONE`).
- `AuthenticatorMiddleware` is an **exact-path whitelist**: unregistered path → 403; registered → authenticator decides (401 on failure). Path-param routes cannot be registered today (Stripe registers concrete enum paths as a workaround).
- `/health-check` is the only GET route; no query-param/pagination conventions exist yet.
- Exception-handler registry: `_api/_handlers/_exception_handlers/` (base + per-domain modules).
- `pyjwt` ^2.13 / `cryptography` 50.0.0 already dependencies (available to 139191's real JWT validation).
- LocalStack `infrastructure/localstack/dynamodb.tf` already defines the table + 3 GSIs → `_api/_test` can exercise the routes end to end.

## Decisions (Q&A round, 2026-10-02)

- **Q1 → A:** routes always registered; route-level guard requires a CF JWT (`cf-access-jwt-assertion` header or `CF-Authorization: Bearer`) → 401 when absent. Full JWT validation + AVP authorization land with OTCM-139191. (Amended 2026-10-08 in PR-7 review: no in-handler guard — enforcement is the whitelist middleware on the custom-auth Lambda only; the IAM URL's perimeter is the platform SigV4. The guard was built, then dropped as double enforcement.)
- **Q2 → exact pattern, own PR:** the whitelist middleware learns to match registered **path templates** (`/transaction-failures/{failure_id}`) — full-path template match, NOT prefix matching (prefixes risk exposing future sibling routes). Shipped as its own PR.
- **Q3 → yes:** default `status=FAILED` applies only to the bare listing; `order_id`/`rice_id` queries without `status` return all statuses (status applied as `FilterExpression` only when explicitly provided). Params are combinable (approach A, posted to the ticket 2026-10-05 for product confirmation): one GSI drives per request — picker priority `order_id` > `rice_id` > `status` — and the rest become `FilterExpression`s; combined queries may return short pages (`Limit` applies pre-filter), so clients rely on `hasMore`. BE page-filling (loop sub-queries until the page fills) was considered and deferred — the cursor stores the last evaluated key, so it can be added later with no contract change.
- **Q4 → yes, configurable:** detail returns the full record (the read model carries no `ttl` — nothing writes it, so there is nothing to exclude); list uses an inclusion set (`_LIST_FIELDS`, the ticket's enumerated fields). `_LIST_FIELDS` is a module-level constant, trivially adjustable.
- **Q5 → 400:** invalid enum (`status`/`sort`), `limit` outside 1–100, `failed_from > failed_to`, malformed cursor, cursor/filter mismatch → 400 (not FastAPI's default 422), scoped to these routes.
- **Q6 → codec with filter hash:** verified against AWS docs — `LastEvaluatedKey` carries only key attributes (table PK + GSI keys), never filter params, and DynamoDB does not validate `ExclusiveStartKey` against the query. Cursor = `base64url(JSON({ "last_evaluated_key": <LastEvaluatedKey>, "filters_hash": <filters-hash> }))`; undecodable or filter-mismatch → 400. (As built in PR 3: adapter-layer step classes, not a domain module — see the PR-3 design section.) Also from the docs: `Limit` applies **before** `FilterExpression` (a page can return fewer than `limit` items) and `hasMore` is driven by the presence of a non-empty `LastEvaluatedKey`, not by page size.
- **Q7 → ticket-only** confirmed.
- **A3 (list omits `invocations`):** list is the ops-queue summary; `invocations` (≤20 debugging maps/item) is detail-view data — the UI columns only need the top-level `last_aws_request_id`. Ticket allows omit-or-truncate.
- **S1 → 3+1 PRs, re-split 2026-10-05 into 8:** the Q2 middleware change is its own PR; PRs 2/3/4 were re-split after the PR-split rule's max dropped to 400 lines (unit tests add +100-300 lines per PR). The CF-JWT authenticator moved into PR 1 (all auth-infra in one reviewed PR; inert until routes land). PR 3 split again on 2026-10-07 into 3a (encoder/hasher) and 3b (decoder) after its 880 lines exceeded reviewable size. PR 6 (facade wiring) was folded into PR 7 later on 2026-10-07: the readers become direct facade attributes with no use-case wrapper (`_use_cases` is a legacy package down to `health_check`; a pass-through wrapper would never gain logic — PR 7 owns validation/serialization in the route layer), and facade/entry-points wiring belongs to the activation PR per the PR-split rule — the series is now 8 PRs.
- **O1 → stage-only:** no prod tag until OTCM-139191 turns enforcement on (shadow mode + presence-only JWT check would otherwise expose failure data on the internet-reachable `NONE`-auth URL).
- **O2 → over-match tests:** PR 1 includes tests proving templates match exactly what is registered and nothing else.
- Assumptions accepted (not flagged): A1 (`/v1/me/permissions` belongs to 139191, not built here), A2 (GSI picker lives in the adapter), A4 (date bounds as `datetime` on the query model — updated from ISO strings in PR-2 review; the adapter converts to ISO strings for the SK BETWEEN / >= / <=; `from > to` → 400), A5 (limit outside 1–100 → 400, not clamped), A6 (reader tolerates missing optional attributes — writer doesn't set retry fields yet), A7 (thin facade wiring — direct reader attributes, no use-case layer, no new Settings keys), A8 (no Terraform/IAM/Cedar in this ticket), A9 (colocated unit tests at 100% + localstack API suite).

## Design

### Port contract (PR 2) — `_domain/_ports/_transaction_failure/`
- `_readers/_transaction_failure_reader.py` — `TransactionFailureReader(ABC)`, `async __call__(query: TransactionFailureQuery) -> TransactionFailurePage`.
- `_readers/_transaction_failure_by_id_reader.py` — `TransactionFailureByIdReader(ABC)`, `async __call__(failure_id: str) -> TransactionFailureRecord | None` (None → route maps 404). Two `__call__` ABCs (repo convention is single-`__call__` ports), so two adapter classes.
- Models (frozen dataclasses, in `_transaction_failure.py` or sibling modules):
  - `TransactionFailureStatus` (plain Enum: FAILED/RETRYING/RESOLVED/IGNORED/DEAD), `TransactionFailureSort` (ASC/DESC). Plain Enum, not `str, Enum`, on purpose: status/sort checks must go through the enum members (`record.status == "FAILED"` never holds), and mypy strict rejects such comparisons as `comparison-overlap`. Every serialization boundary consumes `.value` explicitly: the PR-3 cursor filter hash, the PR-5 Dynamo key/filter values, and the PR-7 route serialization (`asdict` leaves enum members untouched).
  - `TransactionFailureQuery`: `status: TransactionFailureStatus | None`, `rice_id`, `order_id`, `failed_from`, `failed_to` (`datetime | None`), `sort` (default DESC), `limit` (default 50), `cursor: str | None`.
  - `TransactionFailureRecord`: full read model (table attributes except `ttl` — no producer writes it; optional fields `None`-tolerant; counts as `int`).
  - `TransactionFailurePage`: `items: list[TransactionFailureRecord]`, `next_cursor: str | None`; `has_more` is a derived `@property` (`next_cursor is not None`), not a stored field.
- Exceptions (`_domain/_exceptions/_transaction_failure_exceptions.py`): add `TransactionFailureReaderError`, `TransactionFailureInvalidCursorError`.
- Export all public names through `_ports/__init__.py` and `_domain/__init__.py`.

### Cursor codec (PR 3) — `_adapters/_transaction_failure_readers/`

Adapter-layer step classes (the cursor carries a DynamoDB key — an infrastructure concern), sharing the package with PRs 4–5: `TransactionFailureCursorEncoder` / `TransactionFailureCursorDecoder`, each constructed with an injected `TransactionFailureCursorFiltersHasher`; shared test factories in the package `_fixtures.py`. Shipped as two PRs (2026-10-07): 3a encoder + hasher (#2654), 3b decoder (#2652).

- Wire format: unpadded base64url JSON `{last_evaluated_key, filters_hash}` (JOSE convention — `=` is redundant and encodes as `%3D` in URLs). The decoder strict-validates the URL-safe alphabet, the exact payload key set (unknown fields fail closed), `filters_hash` as `str`, and the key as a non-empty dict drawn from the table's key schemas (table PK + every GSI key, the static `_constants.KEY_ATTRIBUTES` set) with string values only — forged keys are rejected at the codec with the 400-mapped error. Deeply nested JSON (`RecursionError`) is caught alongside `ValueError`. (PR 5 wires the decoder statically with `_constants.KEY_ATTRIBUTES` instead of `from_table` — the key set is already known, so no live schema read; `from_table` was later dropped (`96b9a5a27`, 2026-10-12) as nothing in the series calls it.)
- `filters_hash` = sha256 over compact sorted-key JSON of `(status, rice_id, order_id, failed_from, failed_to, sort)` — enum members enter as `.value`; `limit`/`cursor` excluded (page size may change between pages); naive datetimes read as UTC so one instant hashes one way; a bare listing (no `order_id`/`rice_id`) hashes `status` as `FAILED` (the Q3 default), while filtered listings without `status` stay `null`. A drift-guard test pins the hashed field set to the query dataclass fields minus `limit`/`cursor`. The hash is drift detection, not authentication (unkeyed sha256; documented in code).
- Errors: undecodable / malformed / invalid key / filter mismatch → `TransactionFailureInvalidCursorError`. The encoder raises `ValueError` on an empty key (no next page — caller bug) or a non-JSON-serializable key (schema changed — caller bug).

### Dynamo adapters (PRs 4–5) — `_adapters/_transaction_failure_readers/`

- `DynamoTransactionFailureByIdReader` (get, PR 4) and `DynamoTransactionFailureReader` (list, PR 5) in the shared `_transaction_failure_readers` package (one class per module); PR 4 lands the shared item→record mapper that PR 5 reuses; both constructed in `get_adapters()` with `settings.aws_dynamodb_transaction_failures_table_name` + the shared aioboto3 session (mirrors `_transaction_failure_actions`).
- Index picker (first match, never Scan; enum members enter key/filter values as `.value` — boto3 rejects plain Enum members):
  1. `order_id` → `orderId-lastFailedAt`; `status` as `FilterExpression` when provided.
  2. else `rice_id` → `riceId-lastFailedAt`; `status` filter when provided.
  3. else → `status-lastFailedAt` with `status or FAILED` (Q3 default lives here, not in the route).
- SK condition from `failed_from`/`failed_to`: `BETWEEN` / `>=` / `<=` on `last_failed_at` (ISO strings compare lexicographically).
- `ScanIndexForward = (sort == ASC)`; `Limit = limit`; `ExclusiveStartKey` from `decode_cursor`; `next_cursor` from `encode_cursor(LastEvaluatedKey)` when present (`has_more` derives from `next_cursor`).
- Mapper tolerates missing optional attributes (A6); Dynamo `Decimal` → `int` for `occurrence_count`/`retry_count`.
- Unit tests assert `table.scan` is never called (acceptance criterion).

### Activation (PRs 7–8)

- PR 7 wiring (folded in from the dropped PR 6, 2026-10-07): the facade exposes the readers directly — `self.transaction_failure_reader = transaction_failure_reader` / `self.transaction_failure_by_id_reader = ...` (two new `__init__` params next to `transaction_failure_record_action`), no use-case wrapper. `_entry_points.build_monocle_integrations` and `_api/_test/conftest.py` pass the adapter attributes; `_entry_points_unit_test.py` gains the two kwargs in the `assert_called_once_with`; `_monocle_integrations_unit_test.py` gains the two mock kwargs plus identity assertions (`is`, not `isinstance` — pins the no-swap wiring for two same-typed ports). ~15 mechanical lines.
- PR 7 — routes `_api/_routes/_transaction_failure/_transaction_failure_routes.py`:
  - `GET /transaction-failures` — query params parsed by a dependency into a Pydantic model; `ValidationError` → 400 (scoped to these routes, no global handler change). `from > to` → 400 via model validator; `limit` is `ge=1, le=100` (a sub-1 limit otherwise escapes the reader as a raw botocore `ParamValidationError`). Date params are UTC-normalized at parsing (offset-less input rejected or read as UTC) so SK ranges and cursor hashes agree.
  - `GET /transaction-failures/{failure_id}` — 200 / 404. Note: `failure_id` contains `#` → clients must URL-encode (`%23`); called out for the UI ticket.
  - Guard: middleware-only — both routes are registered via `secure_with_cloudflare_jwt`, so the custom-auth Lambda's `AuthenticatorMiddleware` enforces the CF-JWT presence check (401) and fail-closes unregistered paths (403). The IAM URL keeps the platform SigV4 as its only perimeter; an in-handler guard was built and then dropped in review as double enforcement.
  - Whitelist: `CloudflareJwtAuthenticator(BaseAuthenticator)` (presence check; 139191 replaces/extends with real validation + AVP) registered for both route templates via the PR-1 template matching — keeps the custom-auth middleware from 403-ing them.
  - Serialization: list items via `_LIST_FIELDS` inclusion set (ticket's fields; no `invocations`, no raw S3 payload); detail returns the full record (no exclusion set needed — the record carries no `ttl`). `asdict` leaves the plain-Enum `status` untouched, so the serializer maps it to `.value` before building the JSON body. Envelope `{ items, pagination: { nextCursor, hasMore } }`; no `totalCount`.
  - `TransactionFailureInvalidCursorError` → 400 via a new `_exception_handlers` module (only these routes can raise it); reader errors surface as 500 through the base handlers.
- Response field names snake_case as the ticket lists; pagination keys camelCase (`nextCursor`, `hasMore`) per the ticket's JSON example.
